# Markdown Reflection
## Introduction
This reflection will be based on the article “Markdown: A Lightweight Markup Language (2004)” by David M. Berry. The main idea of this article is to provide a brief introduction to Markdown. The article goes through a little bit of everything, starting with a brief context that shows us what Markdown is and why it is important. We are then presented with some basic code examples. These show us how we can use headings, stylized text, lists, and more while using Markdown. The next part of the article gets a little deeper into the concept of Markdown by showing us some of the original code. This allows us to see what the idea of the concept was and what they wanted to prioritize. In the last part of the article, we get the Provocations. This is a way to make us think a little harder about what we are learning about. It provides questions through different viewpoints, such as simplicity, fragmentation, and licensing. Finally, we get our discussion questions. 
## Discussion Questions
1. The idea that Markdown can easily handle normal text, but struggles with things such as tables, implies that it is meant for very simple documents. I believe that Markdown was created to make plain text writing easier. Languages such as HTML can be very difficult to understand, so Markdown creates a way to make the text simpler and easier to create. When it comes to projects that might include data, it is much less effective, as it doesn't have a way to display that clearly.
