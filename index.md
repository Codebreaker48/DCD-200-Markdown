# Markdown Reflection
## Introduction
This reflection will be based on the article *“Markdown: A Lightweight Markup Language (2004)”* by David M. Berry. The main idea of this article is to provide a brief introduction to Markdown. The article covers a bit of everything, starting with brief context that explains what Markdown is and why it is important. We are then presented with some basic code examples. These show us how we can use headings, stylized text, lists, and more while using Markdown. The next part of the article gets a little deeper into the concept of Markdown by showing us some of the original code. This allows us to see what the idea of the concept was and what they wanted to prioritize. In the last part of the article, we get the Provocations. This is a way to make us think a little harder about what we are learning about. It provides questions through different viewpoints, such as simplicity, fragmentation, and licensing. Finally, we get our discussion questions. 
## Personal Reflection
This is my **first** experience with Markdown, and after reading this article, I immediately felt more comfortable with it. Last semester, I used HTML for the first time, and it was a major learning curve, but I don't anticipate that issue with this language. Having that base understanding from last semester is certainly a part of that, but the clear simplicity of Markdown makes me feel very confident in using it. 

After playing around with an empty Markdown file, I was quickly able to use the simple features such as headers, styles, and lists. It took 2 seconds of looking at the article to understand how simple it was to accomplish these tasks. Other tasks, such as links and images, take a little bit more effort, but are still so much easier than in other languages. 

A few of the things that shocked me during this read were how long the original code is and the struggles that Markdown has with things like graphs and tables. I assumed that it would be quite simple, but obviously it isn't as easy as I thought. I guess the complexity of something that looks so simple doesn't come through until you really look at it. The length of the code was a big shocker, simply because I can't fathom having to type or comprehend all of that. It's crazy how all of that can create something so simple.
